# eventual-affine-trace-residue

Eventual affine trace residue in shifted numerical semigroups — a Lean 4 / Mathlib formalization.

For integers k ≥ 2, offsets 0 = r_0 < r_1 < ... < r_k = w with d = gcd(r_1, ..., r_k), and n > 0 with gcd(n, d) = 1, let H_λ be the numerical semigroup generated by n + λw + r_i (0 ≤ i ≤ k). With PF(H) the pseudo-Frobenius numbers, tr(H) = {h ∈ H : ∃ p ∈ PF(H), ∀ f ∈ PF(H), h + p - f ∈ H} and res(H) = |H \ tr(H)|, the record states that there are integers A ≥ 0, B and L ≥ 0 with res(H_λ) = Aλ + B for every integer λ ≥ L (PROOF.md §7 Theorem).

The question is Question 5.4 of D. I. Stamate and F. Strazzanti, *Nearly Gorenstein and almost symmetric
properties in shifted numerical semigroups* (arXiv:2601.19629; J. Pure Appl. Algebra 230 (2026),
doi:10.1016/j.jpaa.2026.108330): is res(M_n + λ r_k) linear in λ for λ ≫ 0? The record answers it affirmatively
under the hypotheses above.

Statements of record (1): `EventualAffineTraceResidue.trace_residue_eventually_affine`. They are stated in `Challenge.lean` and proved in `Solution.lean`; `CORRESPONDENCE.md` maps them to the informal proof.

Status: this file makes no claim about builds or checks. The commands that were run, the commit each ran on and their outputs are the rows of `CORRESPONDENCE.md` §8 ("Build and audit record").

## Layout

- `Challenge.lean` — statements of record (Mathlib-only imports, deliberate `sorry`s). The record section is
  rendered from `records.yaml`.
- `Solution.lean` — states each statement of record again and proves it; does not import `Challenge`. The
  definitions are not repeated there: they are in `EventualAffineTraceResidue/Basic.lean`, with the same text as
  in `Challenge.lean`, and the comparator checks that the two sides agree.
- `EventualAffineTraceResidue/` — the development library.
- `records.yaml` — the ordered list of statements of record; `comparator.json` and `formalization.yaml`
  (`status.main_results`, `alignment.statements`) are rendered from it.
- `docs/PROOF.md` — the informal proof; `CORRESPONDENCE.md` — informal ↔ formal correspondence and the audit
  record.

## Building and checking

```
lake exe cache get
lake build
python3 scripts/check-lean-sources.py
ruby scripts/validate-formalization.rb
./scripts/verify-comparator.sh          # Linux with bubblewrap; runs in CI (job "Check statement against solution")
conductor package check .               # records.yaml ↔ Challenge.lean ↔ comparator.json ↔ formalization.yaml ↔ Solution.lean
```

Pinned toolchain `leanprover/lean4:v4.35.0-rc3`, Mathlib `v4.35.0-rc3`. Never commit `.lake`.

On a conductor host, skip `lake exe cache get`: there `.lake/packages` is a copy-on-write clone of the canonical
prebuilt `.lake` (`conductor lean lake-clone`), and `./scripts/verify-comparator.sh` is left to CI (see
`scripts/README.md`).
